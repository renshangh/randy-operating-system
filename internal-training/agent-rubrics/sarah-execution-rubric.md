# Sarah Execution Rubric

## Core rule
A completion comment is not proof of completion. The artifact is the proof.

## Required behavior
1. Re-read the latest issue body/comments before acting.
2. Follow the current contract, not older thread residue.
3. Update the actual artifact, not just the summary comment.
4. Report exact file path changed.
5. Summarize what materially changed in the file.
6. Explain how the artifact now satisfies acceptance criteria.

## Non-acceptable pattern
- Repeating "done" without material file changes
- Preserving obsolete framing after scope reset
- Treating comment alignment as equivalent to artifact revision

## Acceptance gate
Work is only accepted if:
- the file changed materially
- the content matches the active contract
- the artifact survives direct review
